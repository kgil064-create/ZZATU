## 한 줄 요약

짜투는 **제주도 건축자재 자투리(남은 자재) C2C 거래 플랫폼**이다.
현장에 남은 자재를 사고팔고 나누며, 필요한 자재를 구한다. 모바일 웹.

## 무엇을 검증하려는가 (가장 중요)

**북극성 지표: 문의 발생률.** "매물에 실제로 문의가 오는가"가 이 서비스의 사활이다.

- 순수 연결자 모델이라 거래 완료는 추적 불가(당사자끼리 만나서 끝남).
- 대신 **문의(전화·채팅·댓글)는 추적 가능**하고, 이게 수요의 실재 증거다.
- `item_inquiries` 테이블에 세 경로(`phone`/`chat`/`comment`)가 집계된다.

무엇을 만들지 말지 헷갈릴 때는 **"이게 문의 발생률을 검증하는 데 도움이 되는가"**로 판단한다.

### 지금 단계 (2026년 7월 기준)

- **Seeding 단계.** 목표: 매물 10개, 등록자 4명, 문의 3건.
- 매물을 채우는 게 최우선이고, 기능 추가는 이미 충분하다.
- 성능 최적화·운영자 권한 등은 사용자·매물이 쌓인 뒤로 미뤄둠.
- ⚠️ **관찰된 사실(중요)**: 가입은 되는데 **일반 사용자의 자발적 매물 등록률이 매우 낮다.**
  현재 매물은 전부 내부(길·양이나) 등록. 외부 자발 공급은 사실상 0.
  → 준공 현장 직접 방문 + **"대신 등록"**(사용자는 사진·번호만, 나머지는 운영자가) 방식으로 전환 중.
  → 이게 "진입장벽 문제(A)"인지 "제주 공급 부족(B)"인지 현장 인터뷰로 검증하는 단계.

## 거래 유형 (3종)

| 코드 | 표시명 | 색상(배지/탭) | 의미 |
|---|---|---|---|
| `sell` | 팔아요 | `#0F6E56` 딥틸 | 남은 자재를 판다 |
| `free` | 나눠요 | `#3B6D11` 초록 | 무료로 나눔 |
| `request` | 구해요 | `#854F0B` 앰버 | 자재를 구한다 |
| — | 거래완료 | 회색 | 완료 상태 |

⚠️ **DB에 저장되는 코드(`sell`/`free`/`request`)와 화면 표시명은 다르다.**
표시명을 바꿀 때 DB 코드는 절대 건드리지 말 것. 색은 `ITEM_TYPE_COLORS` 단일 상수에서 관리.

## 핵심 원칙

- **수수료 없음, 재고 없음, 품질 보증 없음.** 순수 연결자다. 이 정체성을 지키는 게 BM 결정의 기준.
- **공급이 수요보다 먼저.** 빈 플랫폼에 사람을 데려오면 3초 만에 나가고 다시 안 온다.
- **되돌리기 어려운 것부터.** 지금 안 하면 영영 못 얻는 데이터(계측·로그)는 먼저,
  나중에 켜도 되는 UI는 나중에.
- **숫자는 문턱 조건부로 노출.** 조회수·찜수는 작을 때 보이면 "죽은 서비스" 신호가 된다.
  수집은 처음부터, 노출은 문턱(조회 20+, 찜 1+) 넘을 때만.

## DB 구조 요약

주요 테이블:

- **`items`** — 매물. `type`, `title`, `item_name`, `price`, `price_option`, `region_id`,
  `delivery_option`, `view_count`, `favorite_count`, `contact_phone`(비공개) 등.
  다중 카테고리는 `item_categories` 조인 테이블.
- **`profiles`** — 회원. `nickname`, `email`, `phone`, `kakao_id` 등.
  ⚠️ **컬럼 권한이 제한됨**: anon·authenticated는 `id`·`nickname`만 SELECT 가능.
  UPDATE는 `nickname`만. (마이그레이션 15)
- **`comments`** — 댓글(구해요에 노출). 1단, 대댓글 없음, 수정 없음, 본인만 삭제.
- **`item_inquiries`** — 문의 집계(북극성 지표). `inquiry_type` = phone/chat/comment.
  본인 매물은 집계 제외. select 정책 없음(운영자만 조회).
- **`search_logs`** — 검색어 집계(비로그인 포함). `log_search` RPC로 기록.
- **`favorites`** — 찜. INSERT/DELETE 시 트리거가 `items.favorite_count` 동기화.
- **`chat_rooms` / `chat_messages`** — 1:1 채팅. `last_read_at` 방식 미확인 배지.
- **`regions`**, **`categories`**, **`transport_options`** — 마스터 테이블.

### 마이그레이션 이력 (`supabase/migrations/`, 01~15)

01~03 초기, 04 storage 정책, 05 phase2 조정, 06 조회, 07 채팅 realtime,
08 회원탈퇴(08_delete_user), 09 찜, 10 배송옵션(10_delivery_option),
11 지역개편(11_regions_restructure), 12 지표집계(12_analytics), 13 댓글(13_comments),
14 채팅읽음(14_chat_read_state), 15 프로필보안(15_profiles_security).

⚠️ 정확한 파일명은 새 마이그레이션 만들기 전 `supabase/migrations/`를 직접 확인할 것.
번호가 겹치지 않게(다른 채팅에서 동시 작업 시 겹칠 위험) 항상 최신 번호를 확인하고 붙인다.

⚠️ **마이그레이션은 Supabase SQL Editor에서 수동 실행**한다(CLI 안 씀).
파일을 만들어도 실행은 사람이 직접 해야 반영된다.

### 알아둘 DB 관례

- RLS 정책 네이밍: `<table>_<action>_<scope>` (예: `comments_insert_own`)
- 인덱스: `idx_<table>_<컬럼>`
- 엔티티 PK: `uuid default gen_random_uuid()`
- 시간 컬럼: `created_at`이 표준. (단 `chat_messages`만 `sent_at`)
- RLS 우회가 필요한 함수/트리거: `SECURITY DEFINER` + `search_path = public` 고정
- 멱등 패턴 필수: `IF NOT EXISTS`, `DROP POLICY IF EXISTS`+`CREATE`, 제약은 `DROP`+`ADD`

## 미뤄둔 것 (의도적 보류)

우선순위 낮음. 사용자·매물이 쌓이면 재검토.

- **성능 최적화** — 매물이 적어 최적화 대상이 없음. 30~50개 쌓인 뒤.
- **운영자 권한** — 용도(신고 처리? 대리 등록?)가 확정되면.
- **가입 시 닉네임 온보딩** — 닉네임 수정은 이미 가능. 자동 안내는 사용자 많아지면.
- **웹 푸시 알림** — VAPID 키는 Vercel 환경변수에 준비됨.
- **profiles의 INSERT/DELETE 권한 정리** — RLS가 이미 막고 있어 낮은 우선순위.
- **자체 로그인(네이버 등)** — 카카오 이탈 근거가 데이터로 보이면. 하더라도 네이버 먼저.
- **AI 사진 자동 채움** — `feat/photo-autofill` 브랜치에 WIP로 보관(로컬 전용, push 안 함).
  코그로보로 만들었으나 실제 키가 로비고스 것이라 엔드포인트·인증 재작업 필요.
  재개: `git switch feat/photo-autofill`. `route.ts`만 업체 종속, 나머지는 재사용.
  ⚠️ 로비고스 엔드포인트가 `http://`면 HTTPS 확인 후 연동할 것(키 평문 전송 방지).
- **아이폰 QA** — 아직 실기 테스트 전. 양이나 님이 체크리스트로 점검 예정.
  채팅 뒤로가기 부재 등 iOS Safari 이슈를 모아서 일괄 수정할 계획.

## 겪은 함정 (재발 주의)

- **`undefined` vs `null`**: supabase-js는 `undefined` 키를 PATCH에서 누락시킨다.
  값을 비우려면 `?? null` 명시.
- **supabase-js 에러**: RLS·CHECK 위반 시 throw하지 않고 `{ error }` 반환.
  `try/catch`로는 안 잡힌다. `error`를 직접 확인할 것.
- **트리거 RLS 차단**: 남이 트리거를 발동시키면 RLS에 막힌다. `SECURITY DEFINER` 필요.
- **컬럼 중복**: 스키마 변경 전 기존 컬럼을 반드시 조사(`display_order`가 이미 있는데
  `sort_order`를 또 만들 뻔함).
- **마이그레이션 미실행**: 파일만 만들고 SQL Editor 실행을 빠뜨리는 일이 잦다.
  검증 쿼리가 0행이면 "실행 안 됨"을 의심.
- **삼성 인터넷 PWA**: WebAPK가 Play 프로텍트에 차단됨. 크롬으로 유도.
- **AI는 QR·한글을 못 그린다**: 팜플렛은 AI로 배경만, QR·글자는 캔바에서.
